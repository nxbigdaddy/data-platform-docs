## 1. Python编码规范

### 1.1 代码风格

遵循 [PEP 8](https://pep8.org/) 规范，使用以下工具进行代码检查：

- **flake8**: 代码风格检查
- **black**: 代码格式化
- **isort**: 导入排序
- **mypy**: 类型检查

### 1.2 命名规范

| 类型 | 规范 | 示例 |
|------|------|------|
| 包名 | 小写，短单词 | `integration`, `governance` |
| 模块名 | 小写，下划线分隔 | `datasource_service.py` |
| 类名 | 大驼峰 | `DatasourceService`, `BaseModel` |
| 函数名 | 小写，下划线分隔 | `get_datasource_by_id()` |
| 变量名 | 小写，下划线分隔 | `datasource_id`, `user_name` |
| 常量名 | 大写，下划线分隔 | `MAX_RETRY_TIMES`, `DEFAULT_TIMEOUT` |
| 私有属性 | 单下划线前缀 | `_internal_method()` |
| 强私有 | 双下划线前缀 | `__private_attr` |

### 1.3 代码格式

```python
# 正确示例
class DatasourceService(BaseService[Datasource]:
    """数据源服务类"""
    
    DEFAULT_TIMEOUT = 30
    MAX_RETRY_TIMES = 3
    
    def __init__(self, db: Session) -> None:
        """初始化服务"""
        super().__init__(db, Datasource)
        self.connector_factory = ConnectorFactory()
    
    def get_by_code(
        self, 
        datasource_code: str,
        include_deleted: bool = False
    ) -> Optional[Datasource]:
        """
        根据编码获取数据源
        
        Args:
            datasource_code: 数据源编码
            include_deleted: 是否包含已删除的数据源
            
        Returns:
            数据源对象，不存在则返回None
        """
        query = self.db.query(Datasource).filter(
            Datasource.datasource_code == datasource_code
        )
        
        if not include_deleted:
            query = query.filter(Datasource.is_deleted == 0)
        
        return query.first()
```

## 3. SQL编码规范

### 3.1 命名规范

```sql
-- 表名：小写，下划线分隔，业务前缀
CREATE TABLE dwd_user_info (...);
CREATE TABLE dws_order_daily (...);

-- 字段名：小写，下划线分隔
user_id BIGINT COMMENT '用户ID',
user_name VARCHAR(128) COMMENT '用户名',
created_at TIMESTAMP COMMENT '创建时间'

-- 索引名：idx_表名_字段名
CREATE INDEX idx_dwd_user_info_user_id ON dwd_user_info(user_id);

-- 约束名：pk_表名, uk_表名_字段名, fk_表名_字段名
CONSTRAINT pk_dwd_user_info PRIMARY KEY (id),
CONSTRAINT uk_dwd_user_info_user_id UNIQUE (user_id)
```

### 3.2 SQL编写规范

```sql
-- 关键字大写，表名字段小写
SELECT 
    user_id,
    user_name,
    created_at
FROM dwd_user_info
WHERE status = 1
    AND created_at >= '2026-01-01'
ORDER BY created_at DESC
LIMIT 100;

-- 使用显式JOIN
SELECT 
    u.user_id,
    u.user_name,
    o.order_id,
    o.order_amount
FROM dwd_user_info u
INNER JOIN dwd_order_info o ON u.user_id = o.user_id
WHERE u.status = 1;

-- 避免SELECT *
-- 错误
SELECT * FROM dwd_user_info;

-- 正确
SELECT user_id, user_name, email FROM dwd_user_info;
```

## 4. Git工作流规范

### 4.1 分支策略

采用 Git Flow 工作流：

```
main (生产分支)
  │
  ├── develop (开发分支)
  │     │
  │     ├── feature/datasource-management (功能分支)
  │     ├── feature/data-quality (功能分支)
  │     │
  │     └── release/v1.0.0 (发布分支)
  │
  ├── hotfix/security-patch (热修复分支)
```

### 4.2 分支命名

| 分支类型 | 命名规范 | 示例 |
|---------|---------|------|
| 功能分支 | feature/{功能描述} | `feature/datasource-management` |
| 修复分支 | bugfix/{问题描述} | `bugfix/connection-timeout` |
| 发布分支 | release/{版本号} | `release/v1.0.0` |
| 热修复分支 | hotfix/{问题描述} | `hotfix/security-patch` |

### 4.3 提交规范

使用 [Conventional Commits](https://www.conventionalcommits.org/) 规范：

```
<type>(<scope>): <subject>

<body>

<footer>
```

**类型说明**：

| 类型 | 说明 |
|------|------|
| feat | 新功能 |
| fix | 修复 |
| docs | 文档 |
| style | 格式（不影响代码运行的变动）|
| refactor | 重构 |
| perf | 性能优化 |
| test | 测试 |
| chore | 构建过程或辅助工具的变动 |

**示例**：

```bash
# 功能提交
git commit -m "feat(datasource): add MySQL connector support

- Implement MySQL connection pool
- Add connection health check
- Support SSL connection

Closes #123"

# 修复提交
git commit -m "fix(api): resolve timeout issue in large query

- Increase default timeout from 30s to 60s
- Add query cancellation support

Fixes #456"

# 文档提交
git commit -m "docs(api): update API documentation for v1.2"
```
