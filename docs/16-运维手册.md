## 2. 日常运维

### 2.1 每日巡检

**巡检时间**：每日 09:00

**巡检内容**：

| 检查项 | 检查方法 | 正常标准 |
|--------|---------|---------|
| 系统可用性 | 访问系统首页 | 可正常访问 |
| 核心服务状态 | `kubectl get pods` | 所有Pod Running |
| 数据库状态 | 连接测试 | 可正常连接 |
| 磁盘空间 | `df -h` | 使用率<80% |
| 内存使用 | `free -h` | 使用率<80% |
| CPU使用 | `top` | 使用率<70% |
| 错误日志 | 查看日志 | 无ERROR级别日志 |

**巡检脚本**：

```bash
#!/bin/bash
# daily-check.sh

echo "=== 数据中台系统每日巡检 ==="
echo "巡检时间: $(date)"

# 检查Pod状态
echo -e "\n[1] 检查Pod状态..."
kubectl get pods -n dmp-prod | grep -v Running | grep -v NAME
if [ $? -ne 0 ]; then
    echo "✓ 所有Pod运行正常"
else
    echo "✗ 存在非Running状态的Pod"
fi

# 检查节点状态
echo -e "\n[2] 检查节点状态..."
kubectl get nodes | grep NotReady
if [ $? -ne 0 ]; then
    echo "✓ 所有节点正常"
else
    echo "✗ 存在NotReady节点"
fi

# 检查磁盘空间
echo -e "\n[3] 检查磁盘空间..."
kubectl exec -it postgres-0 -n dmp-prod -- df -h | awk '$5 > 80 {print}'

# 检查数据库连接
echo -e "\n[4] 检查数据库连接..."
kubectl exec -it postgres-0 -n dmp-prod -- pg_isready
if [ $? -eq 0 ]; then
    echo "✓ 数据库连接正常"
else
    echo "✗ 数据库连接异常"
fi

echo -e "\n=== 巡检完成 ==="
```

## 3. 监控告警

### 3.1 监控大盘

**访问地址**：https://monitoring.dmp.example.com

**核心监控项**：

| 监控项 | 告警阈值 | 告警级别 |
|--------|---------|---------|
| Pod重启次数 | > 3次/小时 | Warning |
| Pod内存使用 | > 85% | Warning |
| Pod CPU使用 | > 80% | Warning |
| 接口响应时间 | > 1s | Warning |
| 接口错误率 | > 1% | Critical |
| 数据库连接数 | > 80% | Warning |
| 磁盘使用率 | > 85% | Warning |
| 磁盘使用率 | > 90% | Critical |

### 3.2 告警处理

**告警级别定义**：

| 级别 | 响应时间 | 处理方式 |
|------|---------|---------|
| Critical | 5分钟 | 立即处理，电话通知 |
| Warning | 30分钟 | 尽快处理，钉钉通知 |
| Info | 4小时 | 日常处理，邮件通知 |

**告警处理流程**：

```
收到告警 → 确认告警 → 定位问题 → 解决问题 → 验证恢复 → 记录归档
    │          │          │          │          │          │
    ▼          ▼          ▼          ▼          ▼          ▼
  查看详情   判断是否    查看日志    执行修复    检查指标    填写报告
  通知值班   误报        分析原因    操作        确认恢复
```

### 3.3 常见告警处理

#### 告警：Pod重启

**处理步骤**：

1. 查看Pod状态和事件
```bash
kubectl describe pod <pod-name> -n dmp-prod
```

2. 查看Pod日志
```bash
kubectl logs <pod-name> -n dmp-prod --previous
```

3. 分析重启原因：
   - OOMKilled：内存不足，增加内存限制
   - Error：应用错误，查看日志修复
   - Evicted：节点资源不足，扩容节点

4. 执行修复操作

#### 告警：数据库连接池耗尽

**处理步骤**：

1. 查看当前连接数
```sql
SELECT count(*) FROM pg_stat_activity;
```

2. 查看活跃连接
```sql
SELECT * FROM pg_stat_activity WHERE state = 'active';
```

3. 清理空闲连接
```sql
SELECT pg_terminate_backend(pid) FROM pg_stat_activity 
WHERE state = 'idle' AND state_change < NOW() - INTERVAL '1 hour';
```

4. 调整连接池配置

## 4. 故障处理

### 4.1 故障分级

| 级别 | 定义 | 响应时间 | 处理目标 |
|------|------|---------|---------|
| P0 | 系统完全不可用 | 5分钟 | 30分钟恢复 |
| P1 | 核心功能不可用 | 15分钟 | 1小时恢复 |
| P2 | 部分功能异常 | 1小时 | 4小时恢复 |
| P3 | 轻微问题 | 4小时 | 24小时恢复 |

### 4.2 故障处理流程

```
故障发现 → 故障定级 → 故障处理 → 故障恢复 → 复盘总结
    │          │          │          │          │
    ▼          ▼          ▼          ▼          ▼
  监控告警   评估影响   定位原因   验证修复   根因分析
  用户反馈   确定级别   执行修复   恢复服务   改进措施
```

### 4.3 常见故障处理

#### 故障：服务无法访问

**排查步骤**：

1. 检查网络连通性
```bash
ping dmp.example.com
curl -I https://dmp.example.com
```

2. 检查Ingress状态
```bash
kubectl get ingress -n dmp-prod
kubectl describe ingress dmp-ingress -n dmp-prod
```

3. 检查Service状态
```bash
kubectl get svc -n dmp-prod
```

4. 检查Pod状态
```bash
kubectl get pods -n dmp-prod
```

5. 查看Pod日志
```bash
kubectl logs -l app=dmp-gateway -n dmp-prod
```

#### 故障：数据库主从切换

**处理步骤**：

1. 确认主库故障
```bash
kubectl exec -it postgres-0 -n dmp-prod -- pg_isready
```

2. 手动提升从库为主库
```bash
kubectl exec -it postgres-1 -n dmp-prod -- pg_ctl promote
```

3. 更新应用连接配置
4. 修复原主库
5. 重新配置主从关系

#### 故障：数据丢失

**处理步骤**：

1. 确认丢失范围和时间点
2. 停止相关写入操作
3. 从备份恢复数据
```bash
# 恢复PostgreSQL
pg_restore -h localhost -U dmp_admin -d dmp_metadata /backup/postgres/20260331/dmp_metadata.dump
```

4. 验证数据完整性
5. 恢复写入操作

## 5. 扩容操作

### 5.1 应用扩容

**水平扩容**：

```bash
# 手动扩容
kubectl scale deployment dmp-integration-service --replicas=5 -n dmp-prod

# 查看扩容结果
kubectl get pods -l app=dmp-integration-service -n dmp-prod
```

**自动扩容配置**：

```yaml
# hpa.yaml
apiVersion: autoscaling/v2
kind: HorizontalPodAutoscaler
metadata:
  name: dmp-integration-service-hpa
spec:
  scaleTargetRef:
    apiVersion: apps/v1
    kind: Deployment
    name: dmp-integration-service
  minReplicas: 3
  maxReplicas: 10
  metrics:
    - type: Resource
      resource:
        name: cpu
        target:
          type: Utilization
          averageUtilization: 70
```

### 5.2 数据库扩容

**PostgreSQL扩容**：

```bash
# 垂直扩容 - 修改资源配置
kubectl patch statefulset postgres -n dmp-prod --type='json' -p='[
  {"op": "replace", "path": "/spec/template/spec/containers/0/resources/limits/memory", "value": "4Gi"}
]'

# 水平扩容 - 增加只读副本
kubectl scale statefulset postgres --replicas=3 -n dmp-prod
```

**ClickHouse扩容**：

```bash
# 增加分片
kubectl scale statefulset clickhouse --replicas=6 -n dmp-prod
```

## 6. 备份恢复

### 6.1 备份策略

| 数据类型 | 备份方式 | 备份频率 | 保留期限 |
|---------|---------|---------|---------|
| PostgreSQL | 物理备份+逻辑备份 | 每日 | 30天 |
| ClickHouse | 分区备份 | 每日 | 7天 |
| Redis | RDB+AOF | 每小时 | 7天 |
| 配置文件 | Git版本控制 | 变更时 | 永久 |

### 6.2 备份操作

**PostgreSQL备份**：

```bash
#!/bin/bash
# backup-postgres.sh

BACKUP_DIR="/backup/postgres/$(date +%Y%m%d)"
mkdir -p $BACKUP_DIR

# 逻辑备份
kubectl exec -it postgres-0 -n dmp-prod -- pg_dumpall -U dmp_admin > $BACKUP_DIR/all_databases.sql

# 压缩
gzip $BACKUP_DIR/all_databases.sql

# 上传到对象存储
mc cp $BACKUP_DIR/all_databases.sql.gz minio/backup/postgres/

# 清理旧备份（保留30天）
find /backup/postgres -type d -mtime +30 -exec rm -rf {} \;
```

### 6.3 恢复操作

**PostgreSQL恢复**：

```bash
#!/bin/bash
# restore-postgres.sh

BACKUP_FILE=$1

# 停止应用
kubectl scale deployment dmp-integration-service --replicas=0 -n dmp-prod

# 恢复数据
kubectl exec -i postgres-0 -n dmp-prod -- psql -U dmp_admin < $BACKUP_FILE

# 启动应用
kubectl scale deployment dmp-integration-service --replicas=3 -n dmp-prod

# 验证
kubectl exec -it postgres-0 -n dmp-prod -- psql -U dmp_admin -c "SELECT count(*) FROM information_schema.tables;"
```

## 7. 安全运维

### 7.1 安全巡检

**每日安全巡检**：

```bash
#!/bin/bash
# security-check.sh

echo "=== 安全巡检 ==="

# 检查异常登录
echo "[1] 检查异常登录..."
kubectl exec -it postgres-0 -n dmp-prod -- psql -U dmp_admin -c "SELECT * FROM sec_audit_log WHERE operation_type='login' AND operation_time > NOW() - INTERVAL '1 day';"

# 检查权限变更
echo "[2] 检查权限变更..."
kubectl exec -it postgres-0 -n dmp-prod -- psql -U dmp_admin -c "SELECT * FROM sec_audit_log WHERE operation_type LIKE '%permission%' AND operation_time > NOW() - INTERVAL '1 day';"

# 检查漏洞扫描
# trivy image --severity HIGH,CRITICAL registry.example.com/dmp/backend:latest

echo "=== 安全巡检完成 ==="
```

### 7.2 安全事件响应

**安全事件处理流程**：

1. **发现**：监控告警或安全报告
2. **确认**：验证安全事件真实性
3. **遏制**：隔离受影响系统
4. **根除**：清除安全威胁
5. **恢复**：恢复系统服务
6. **总结**：分析原因，改进措施
